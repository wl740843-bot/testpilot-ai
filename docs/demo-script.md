# TestPilot AI 项目演示脚本（Day 19）

> 总时长：约 3 分半（可压缩到 3 分钟）。括号内为每段预计时长。
> 演示前准备：终端已激活虚拟环境、已执行 `streamlit run app.py`、浏览器已打开 `http://localhost:8501`。

---

## 第 0 步：开场白（约 30 秒）

> 讲解词：
> "这是我用 3 周开发的 **TestPilot AI 测试助手**：输入一段功能需求，自动生成结构化测试用例；还能分析 pytest 报错日志，给出初步排查建议。先看第一个功能。"

---

## 第 1 步：输入需求 → 生成测试用例（约 45 秒）

**操作动作：**
1. 页面顶部**模型模式**选择「强制演示模式」（或保持默认自动，未配 Key 时即为演示模式）
2. 在需求输入框输入 `登录功能`
3. 点击「生成测试用例」

**预期画面：** 绿色提示"已生成 3 条测试用例（演示模式）"，下方表格出现 3 条用例：正常流程 / 异常输入 / 边界值。

**讲解词：**
> "我输入'登录功能'，点击生成，系统立刻给出 3 条用例：正常流程、异常输入、边界值。每条用例有 6 个固定字段：标题、前置条件、步骤、预期结果、优先级、测试类型。"
> "如果不配置 API Key，系统用内置模板生成，可以离线运行——这就是演示模式。"

**对应截图：** `docs/screenshots/home.png`

---

## 第 2 步：用例编辑 + Excel 导出（约 30 秒）

**操作动作：**
1. 点击表格里的单元格，直接修改内容（如把某条用例的优先级改成"低"）
2. 点击「下载 Excel 用例表」

**讲解词：**
> "表格是可以在线编辑的——比如我直接改优先级，改完点'下载 Excel 用例表'，就导出成 .xlsx，Excel 或 WPS 都能打开。"

**对应截图：** `docs/screenshots/cases_download.png`

---

## 第 3 步：pytest 日志分析（约 45 秒）

**操作动作：**
1. 页面下方找到「pytest 日志分析」
2. 在输入框粘贴一段真实的 pytest 失败日志（见下方示例）
3. 点击「分析日志」

**示例日志（可直接粘贴）：**

```text
============================================================
FAILED tests/test_login.py::test_login_empty_password - AssertionError
tests/test_login.py:12: in test_login_empty_password
    assert login("", "123456") == "密码不能为空"
E   AssertionError: assert '请输入用户名' == '密码不能为空'
============================================================
```

**预期画面：** 显示"发现线索"（第 2 行、第 5 行出现 AssertionError）+ "排查建议"（断言失败：期望值和实际值不一致……）+ 底部免责声明。

**讲解词：**
> "把 pytest 的报错日志贴进来，点分析，它先定位报错关键词在第几行，再给出排查建议。"
> "注意底部这句话：**以上为初步排查建议，仅供参考，不构成已确认的故障原因**——日志分析是线索，不是结论，真正的根因要靠我们自己看 traceback 确认。"

**对应截图：** `docs/screenshots/log_analysis.png`

---

## 第 4 步：pytest 测试结果（约 30 秒）

**操作动作：**
1. 切换到终端，执行：

```powershell
python -m pytest tests
```

**预期画面：** `73 passed in 1.42s`

**讲解词：**
> "项目有 73 个单元测试全部通过：核心逻辑 35 个、异常与边界 32 个、日志落盘与切割 6 个。测试默认不发起真实网络请求，全部用 monkeypatch 模拟，所以不消耗 API 费用。"
